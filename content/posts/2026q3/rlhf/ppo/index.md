提到 RLHF（Reinforcement Learning from Human Feedback）时，PPO 几乎是绕不开的名字。早期 ChatGPT 等一批对齐系统的公开技术路线里，常见的就是一条经典链路：`预训练 -> SFT -> 奖励模型 -> PPO`。

很多人第一次接触 PPO，会觉得它“公式很多、工程很重、细节很绕”。但如果只抓住一个核心，它其实不难理解：

> PPO 要解决的，不是“如何让模型变好”这么抽象的问题，而是“如何在根据奖励优化策略时，不要一下子走太猛，把模型训崩”。

这篇文章我想把 PPO 讲清楚，重点放在三个问题上：

1. 为什么在 RLHF 里会需要 PPO。
2. PPO 的核心公式到底在约束什么。
3. 为什么它后来又逐渐被 DPO 一类更轻的方法替代。

## 为什么 RLHF 需要 PPO

先看一个很朴素的目标。

假设我们已经有了一个 SFT 模型，它已经会说话、会跟随指令，但回答还不够“符合人类偏好”。比如：

- 有时太啰嗦
- 有时不够有帮助
- 有时会输出风险内容
- 有时会用一种“看起来正确但其实不可靠”的方式回答

于是我们收集人类偏好数据，训练一个奖励模型（Reward Model），让它学会给回答打分。然后我们就希望直接优化语言模型，让它生成能拿到更高奖励的回答。

问题在于，语言模型的输出空间极大，奖励模型本身也不是完美真理。如果我们只做最朴素的“谁奖励高就往谁那边猛推”，策略很容易出现几个问题：

1. 更新步子太大，模型分布瞬间偏离原来的 SFT 分布。
2. 模型开始钻奖励模型的空子，出现 reward hacking。
3. 训练不稳定，前几步看起来奖励上涨，后面生成质量整体下滑。

所以 RLHF 并不是“有了奖励模型就直接暴力优化”这么简单。它需要一个相对稳健的策略优化方法，让模型在提高奖励的同时，不要偏离太快。PPO 之所以流行，就是因为它在“能优化”和“别失控”之间找到了一个工程上可用的平衡点。

## 从策略梯度开始理解

PPO 属于策略梯度（Policy Gradient）方法这一脉。

在强化学习里，策略就是一个概率分布：

$$
\pi_\theta(a|s)
$$

表示在状态 $s$ 下选择动作 $a$ 的概率，参数是 $\theta$。

对于语言模型来说，也可以做一个近似对应：

- 状态 $s$：当前的 prompt 和已经生成的前文
- 动作 $a$：下一个 token
- 策略 $\pi_\theta$：模型输出下一个 token 的概率分布

也就是说，LLM 在 RLHF 里本质上也能看成一个策略模型。

最基础的策略梯度目标可以写成：

$$
\nabla_\theta J(\theta) = \mathbb{E}\left[\nabla_\theta \log \pi_\theta(a_t|s_t) A_t\right]
$$

其中 $A_t$ 是 advantage（优势函数），可以理解成：

- 这个动作比“平均水平”更好，则 $A_t > 0$
- 这个动作比“平均水平”更差，则 $A_t < 0$

这个公式的意思很直接：

- 如果某个动作带来了更好的结果，就提高它的概率
- 如果某个动作带来了更差的结果，就降低它的概率

看起来很合理，但直接这么做有个老问题：**更新可能非常不稳定**。某一批数据里某些动作优势特别大时，模型就可能被推得过猛，导致新策略和旧策略差异过大。

## PPO 的核心：限制策略不要一步走太远

PPO 的全称是 Proximal Policy Optimization。`Proximal` 可以理解成“近端的、不要离太远的”。

它的关键思想是：每次更新策略时，新策略可以变好，但不能相对旧策略偏移过头。

为此，PPO 引入了一个概率比值：

$$
r_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\text{old}}}(a_t|s_t)}
$$

这个比值表示：

- 如果 $r_t(\theta) > 1$，说明新策略更倾向于这个动作
- 如果 $r_t(\theta) < 1$，说明新策略降低了这个动作的概率

如果我们直接优化：

$$
r_t(\theta) A_t
$$

那当 $A_t$ 很大时，模型仍然可能更新过猛。所以 PPO 做了一个非常经典的裁剪（clip）：

$$
L^{\text{CLIP}}(\theta) =
\mathbb{E}\left[
\min\left(
r_t(\theta) A_t,\;
\text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) A_t
\right)
\right]
$$

这就是 PPO 最核心的目标函数。

如果只讲直觉，它的含义是：

- 当一个动作是好动作（$A_t > 0$）时，你可以提高它的概率
- 但提高也不能太多，超过阈值就不再继续鼓励
- 当一个动作是坏动作（$A_t < 0$）时，你可以降低它的概率
- 但降低也不能太猛，避免训练震荡

也就是说，PPO 不是不让模型变，而是给“变”的幅度装了个保险杠。

## 一个更直观的例子

假设模型回答一个问题时，有一个 token 或一个片段明显让奖励模型更满意，那么它的 advantage 是正的。

这时优化会推动模型在未来更倾向生成这个片段。但如果原来这个片段的概率是 0.02，新策略一下子把它推到 0.20，这通常就是很危险的信号，因为分布变形太大了。

PPO 会说：可以涨，但别暴涨。

反过来，如果某个回答片段非常差，模型确实应该减少它的概率，但如果直接从“偶尔会说”变成“几乎绝不会说”，又可能把模型整体语言能力一起拉坏。PPO 同样会限制这种剧烈下降。

所以你可以把 PPO 理解成一种“带刹车的奖励优化”。

## PPO 在 RLHF 里的具体训练流程

把 PPO 放回 RLHF 语境里，它通常长这样：

### 1. 先有一个 SFT 模型

这一步得到的是初始策略 $\pi_\theta$。它已经具备基本对话能力，否则后面的强化学习没有稳定起点。

### 2. 训练奖励模型

奖励模型通常来自偏好数据。给定同一个 prompt，人类会在两个回答里选出更好的那个。奖励模型学的是：

> 哪种回答更符合人类偏好。

训练完成后，它可以对模型生成的回答打一个标量分数。

### 3. 用当前策略采样回答

对一批 prompt，让当前语言模型生成 completion。这里是 on-policy 的关键步骤，因为 PPO 需要用当前策略采到的数据来更新当前策略。

### 4. 计算奖励

在 RLHF 里，奖励往往不只是奖励模型的分数，还会加上一个对参考模型的 KL 惩罚。常见写法类似：

$$
R(x, y) = r_\phi(x, y) - \beta \, \mathrm{KL}\big(\pi_\theta(\cdot|x)\; || \; \pi_{\text{ref}}(\cdot|x)\big)
$$

其中：

- $r_\phi(x, y)$ 是奖励模型给回答 $y$ 的分数
- $\pi_{\text{ref}}$ 往往是冻结的 SFT 参考模型
- KL 惩罚用来防止当前策略偏离参考策略太远

这里很重要的一点是：**RLHF 里的 PPO，本身已经不是原始教科书 PPO，而是带有参考分布约束的 PPO 变体。**

### 5. 估计 value 和 advantage

为了降低方差，PPO 往往不是直接拿最终 reward 生推，而是会训练一个 value model，估计状态价值，再构造 advantage。

简化理解就是：

$$
A_t = R_t - V(s_t)
$$

真实工程里常见的是 token 级别 value、return、GAE 等组合，这部分会让 PPO 的实现显著复杂起来。

### 6. 多轮 mini-batch 更新策略

有了旧策略采样出来的数据后，PPO 会在这些数据上做若干轮 mini-batch 优化，目标就是前面的 clipped objective。

这也是 PPO 工程上“既实用又麻烦”的地方：

- 它比 REINFORCE 稳定得多
- 但它需要 actor、critic、reward model、reference model 一整套系统协同

## PPO 为什么在 RLHF 里有效

PPO 在 RLHF 里有效，核心不是因为它“最优”，而是因为它在大模型对齐早期满足了几个现实条件。

### 1. 它能直接优化一个显式奖励

一旦你已经训练出了奖励模型，PPO 可以非常自然地把“提高奖励”变成训练目标。这让“人类偏好”第一次能够比较系统地注入语言模型。

### 2. 它比朴素策略梯度稳定

clip 机制和 KL 约束都在做一件事：别让模型为了短期奖励迅速漂移。这对语言模型尤其重要，因为语言模型一旦分布塌掉，坏掉的不只是一个动作，而是整段生成风格和能力边界。

### 3. 它有成熟的强化学习工程经验可借

PPO 本来就是深度强化学习里应用很广的方法，工业界对它的优化流程、并行采样、value baseline、GAE、batch update 等机制已经相对熟悉，所以它成为 RLHF 早期的自然选择。

## PPO 的代价和局限

虽然 PPO 很经典，但它并不“轻”。

### 1. On-policy，训练成本高

PPO 需要当前策略不断采样新数据，不能像普通监督学习那样直接把固定数据集来回刷很多遍。对 LLM 来说，这意味着：

- 需要频繁生成样本
- 训练吞吐低
- 整体成本高

这也是为什么“大模型 RLHF 很贵”这件事，PPO 要背很大一部分锅。

### 2. 系统复杂，调参重

实际训练里，你通常要同时关心：

- learning rate
- clip range
- KL 系数
- reward scale
- value loss
- entropy bonus
- rollout 长度
- batch size 和 update epoch

这些参数一旦搭配不好，就容易出现奖励波动、KL 爆炸、模式坍塌或者回答风格变形。

### 3. 奖励模型不是真实目标

PPO 优化的是奖励模型给出的信号，而不是“真正的人类满意度”本身。如果奖励模型有偏差，PPO 只会更高效地放大这种偏差。

所以很多人说 PPO 会 reward hack，本质上不是 PPO 发明了这个问题，而是它把“优化代理目标”的能力做强了。

### 4. 对语言建模来说并不天然优雅

PPO 原本是为一般强化学习问题设计的，迁移到自回归语言模型后，需要做很多适配：

- token 级动作定义
- 序列级奖励回传
- 长文本 credit assignment
- 参考模型 KL 控制

这些东西能做，但并不简洁。

## 为什么后来很多工作转向 DPO

如果说 PPO 代表的是“先学奖励模型，再做强化学习”，那么 DPO（Direct Preference Optimization）代表的是另一条思路：

> 不显式跑完整个 RL 流程，直接把偏好数据转成一个更像监督学习的优化目标。

DPO 之所以后来很火，很大程度上就是因为它避开了 PPO 的几个重负担：

- 不需要单独训练 value model
- 不需要在线 rollout
- 不需要一整套复杂 RL 训练基础设施
- 工程更简单，成本更低

这并不意味着 PPO 失效了，而是说明在很多大模型对齐场景里，大家发现“更轻、更稳、更容易复现”的方法往往更有吸引力。

但反过来说，理解 PPO 仍然非常重要。因为只要你想认真理解 RLHF 的历史主线、奖励优化的本质、KL 约束为什么重要，最后还是会回到 PPO。

## 我的理解：PPO 的历史价值大于它今天的默认地位

如果站在今天看，PPO 在大模型对齐里已经不再是唯一主角，但它依然有非常高的认知价值。

它至少把三件事讲明白了：

1. 大模型可以被当作策略来优化。
2. 人类偏好可以通过奖励信号进入训练过程。
3. 对齐训练的关键从来不是“拼命优化”，而是“受控优化”。

某种意义上，PPO 是 RLHF 时代最有代表性的“第一代标准答案”。它不一定是最终答案，但它把问题空间打开了。

## 小结

一句话总结 PPO：

> PPO 是一种为了让策略更新更稳定而设计的强化学习方法，在 RLHF 里，它通过 clipped objective 和 KL 约束，让语言模型在提升人类偏好奖励的同时，不至于迅速偏离原有能力分布。

如果再压缩成三个关键词，就是：

- `奖励优化`
- `限制漂移`
- `工程可用`

理解 PPO，最重要的不是背公式，而是明白它试图解决的张力：

> 你既希望模型更听人话，又不能为了“更听话”把模型本身训坏。

这正是 PPO 在 RLHF 里存在的意义。
